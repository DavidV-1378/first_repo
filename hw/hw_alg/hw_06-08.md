### H1 — best fixed-length block

Return `(start, total)` for the consecutive block of exactly size values with largest sum. Ties keep the earliest start. Raise ValueError for size <= 0 or size > input length.

```text
[4, -1, 2, 7, -3, 5], size=3 -> (3, 9)
[-5, -2, -8], size=2 -> (0, -7)
[2, 2, 2], size=2 -> (0, 4)
```

Signature: `best_block(values: list[int], size: int) -> tuple[int, int]`.

### H2 — frequency report

Return `(value, count)` records ordered by count descending. Ties retain first-appearance order. Empty input gives an empty list.

```text
["A", "B", "B", "A", "C"] -> [("A", 2), ("B", 2), ("C", 1)]
```

Signature: `frequency_report(values: list[str]) -> list[tuple[str, int]]`.

### H3 — requests with cancellation

Process events in order:

- `('add', id)`: add a request at the back.
- `('cancel', id)`: cancel a waiting request.
- `('serve', '')`: serve the oldest request still waiting; do nothing if none remain.

Return served IDs in processing order. Every ID is added at most once. Cancellation always refers to a waiting request. Actions are guaranteed valid; validation of those guarantees is not required. ID reuse is outside the contract.

```text
[("add", "A"), ("add", "B"), ("cancel", "A"),
 ("serve", ""), ("add", "C"), ("serve", "")]
-> ["B", "C"]
```

Signature: `served_requests(events: list[tuple[str, str]]) -> list[str]`.

Test empty service, cancellation in the middle, all requests cancelled, and requests still waiting at the end.

### H2.3 — recent repeat arrivals, applied integrator

Events are `(timestamp, user)` pairs in nondecreasing timestamp order; equal timestamps are allowed. For each arrival at time t, flag its input index if the same user appeared earlier at a time strictly greater than `t - span`. The current event must not count as its own earlier occurrence. Exactly span units ago is expired. Return flagged indices in input order. span must be positive or raise ValueError. Empty events return an empty list; preserve input. The sorted timestamp precondition is guaranteed.

```text
events = [(0, "A"), (2, "B"), (4, "A"), (7, "A"), (9, "B")]
span = 5
result = [2, 3]
```

At t=7, entries at times 0 and 2 expire, but A at time 4 still qualifies. At t=9, B at time 2 is too old. `[(0, 'A'), (5, 'A')]` with span 5 gives `[]`.

Each arrival enters and leaves the deque at most once: expected O(n) total time. Extra working space is proportional to active arrivals/users, plus the output. The exact timestamp expiration requirement is new, but deque operations and entering/leaving counts were taught. Test equal timestamps, multiple active copies of one user, boundary expiration, long gaps, negative ordered timestamps, and empty input.
